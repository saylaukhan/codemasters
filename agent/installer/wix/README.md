# Установщик агента (WiX v4)

`VKO-Agent.msi` ставит агент «Мониторинг интернета ВКО» на компьютер школы: службу
`VKOMonitorAgent` с отложенным автозапуском, папку данных и файл конфигурации. GUI и значка в
трее нет — после установки участие пользователя не требуется (ТЗ п. 2, ADR-010).

Собирается в CI: `.github/workflows/agent-msi.yml`. Локально MSI не собирается — нужен
Windows и WiX; `make check-agent` установщик не трогает.

## Что делает установка

1. Кладёт `vko-agent.exe` в `C:\Program Files\VKO Monitor\`.
2. Создаёт `C:\ProgramData\VKO Monitor\` и даёт учётной записи LocalService право писать туда:
   там живут очередь замеров (`queue.db`), журнал, `device.json` и токен устройства.
3. Вызывает `vko-agent configure` — тот пишет `C:\ProgramData\VKO Monitor\agent.yaml` из
   параметров установки и задаёт перезапуск службы после сбоя (1 мин / 1 мин / 5 мин).
4. Регистрирует службу `VKOMonitorAgent`: тип запуска «Автоматически (отложенный запуск)»,
   учётная запись LocalService, правило брандмауэра только на исходящие соединения.
5. Запускает службу. При первом старте агент регистрируется на сервере кодом установки и
   получает `device_id` и токен (T-07); дальше замеряет по расписанию с сервера (ADR-012).

## Параметры установки

| Параметр | Обязательный | Что это |
|---|---|---|
| `ENROLL_CODE` | нет | одноразовый код установки из панели, привязывает ПК к школе (T-07) |
| `ROOM` | нет | кабинет, в котором стоит компьютер |
| `SERVER_URL` | да | адрес API сервера мониторинга; значение по умолчанию зашивается при сборке |
| `LOG_LEVEL` | нет | `debug`, `info` (по умолчанию), `warn`, `error` |

Тихая установка, в том числе через групповые политики (plan.md §4.1):

```bat
msiexec /i VKO-Agent.msi /qn ENROLL_CODE=VKO-7F3K-92QD ROOM="Серверная"
```

Свой сервер:

```bat
msiexec /i VKO-Agent.msi /qn ENROLL_CODE=VKO-7F3K-92QD ROOM="Серверная" SERVER_URL=https://monitor.example.kz
```

Без `ENROLL_CODE` установка проходит, но устройство не регистрируется: агент пишет об этом в
журнал и ждёт. Код можно дописать в `agent.yaml` и перезапустить службу.

## Проверка после установки

```bat
sc qc VKOMonitorAgent          REM START_TYPE : 2 AUTO_START (DELAYED)
sc qfailure VKOMonitorAgent    REM RESET_PERIOD 86400, RESTART 60000 / 60000 / 300000
"C:\Program Files\VKO Monitor\vko-agent.exe" status
```

`status` печатает состояние службы, зарегистрировано ли устройство, последний замер и размер
очереди.

## Удаление

Через «Программы и компоненты» или `msiexec /x VKO-Agent.msi /qn`. Служба останавливается и
удаляется, `vko-agent.exe` убирается.

Папка `C:\ProgramData\VKO Monitor\` остаётся намеренно: в ней лежат неотправленные замеры
(ADR-006) и токен устройства. Повторная установка подхватит их и не потребует нового кода.
Чтобы поставить ПК заново «с нуля» — удалить папку руками после удаления программы и
заблокировать старое устройство в админке (ТЗ п. 20).

## Обновление версии

MSI собирается с `ProductVersion` из тега (`v1.2.3` → `1.2.3`) или `0.1.<номер прогона>` без
тега. Установка более новой версии поверх старой снимает старую сразу после начала установки
(`MajorUpgrade`), папку данных и очередь не трогает, код установки и кабинет из `agent.yaml`
сохраняет.

## Подпись

MSI не подписан: сертификата Authenticode у заказчика пока нет («Решения по умолчанию»
в `docs/tasks/README.md`). Windows SmartScreen при ручном запуске покажет предупреждение;
тихая установка через групповые политики от этого не страдает. Шаг подписи закомментирован в
`.github/workflows/agent-msi.yml` и включается одной строкой, когда сертификат появится.
Строка — в `docs/known-limitations.md`.

## Файлы

| Файл | Что в нём |
|---|---|
| `Package.wxs` | весь установщик: папки, компоненты, служба, брандмауэр, действие `configure` |

Переменные препроцессора приходят из CI ключами `-d`: `Version` (числовая версия MSI),
`AgentExe` (путь к собранному `vko-agent.exe`), `ServerUrl` (значение `SERVER_URL` по умолчанию).
