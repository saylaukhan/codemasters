# ADR-008 · Роли и область видимости: permissions в API + RLS в PostgreSQL

**Статус:** принято · **Дата:** 2026-09-16 · **Источник:** ТЗ п. 12, п. 16, п. 20, plan.md §5, §9

## Контекст
ТЗ п. 16 требует пять ролей, применение прав «как к веб-панели, так и к API», блокировку учётной
записи без удаления истории и журнал аудита; провайдер не должен видеть чужих поставщиков. Проверка
«внутри роутера» держится на дисциплине: одна забытая проверка — и чужие школы видны всем.

## Решение
- Ролей ровно пять (ТЗ п. 16): Школа, Район/город, Область, Провайдер, Администратор. Таблицы
  `users`, `roles`, `user_scopes` (`region_id` / `provider_id` / `school_id`) — plan.md §5.
- Слой 1 — API: каждый эндпоинт объявляет dependency `require("<permission>")` из `app/auth`.
- Слой 2 — БД: таблицы с областью видимости получают RLS-политику по переменной сессии `app.user_scope`,
  которую выставляет `app/auth/rls.py` на каждый запрос. Неверный запрос в коде чужих строк не отдаст.
- Школа видит свой `school_id`; Район/город — школы своего `region_id`; Провайдер — линии своего
  `provider_id` и их школы; Область и Администратор — всю ВКО.
- Блокировка — `users.is_active = false`; строки пользователя и `audit_log` не удаляются никогда.
  Устройства — так же, без удаления замеров (ADR-005 «Идентичность устройства и защита от подмены»).
- Аудит: middleware в `app/main.py` пишет входы и все изменяющие действия в `audit_log` (п. 12, п. 16).

## Последствия
- Новая таблица с областью видимости обязана иметь RLS-политику и тест в `backend/tests/`; новый
  эндпоинт — `require(...)` и тест «чужой не видит». Проверяется по `docs/checklist.md` перед слиянием.
- Цена — миграции с политиками и тесты на живом Postgres; взамен изоляцию гарантирует база, а не внимательность.
- Кода пока нет: появится в T-20; админка пользователей — T-38, журналы аудита — T-39.

## Открыто
- Матрица «роль → permission» не зафиксирована. До неё — plan.md §9 и правило: Область — пороги, расписания,
  правила инцидентов, справочники; Администратор — то же плюс пользователи, устройства, релизы агента, журналы.
