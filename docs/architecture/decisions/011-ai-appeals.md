# ADR-011 · AI-обращения через адаптер, без ПД

**Статус:** принято · **Дата:** 2026-09-16 · **Источник:** ТЗ п. 12, п. 15, п. 17, plan.md §8, §10

## Контекст
ТЗ п. 17 требует генерировать проект официального обращения поставщику с помощью AI, давать его на правку
до отправки, присваивать номер после отправки и вести историю статусов. Контакты ответственных (п. 15) —
персональные данные, а п. 12 запрещает собирать лишнее: ФИО и телефоны во внешний сервис уходить не должны.
Заказчик может потребовать закрытый контур без внешних API.

## Решение
- Один адаптер `LLMProvider` в `app/services/llm/`: по умолчанию Claude API, для закрытого контура — Ollama; выбор — настройкой.
- Контекст для модели собирает сервер (plan.md §8): School ID, школа, поставщик, договор, период, агрегаты
  Download/Upload/Ping/Jitter/Packet Loss, применённые пороги, число и длительность простоев, выдержка
  замеров. ФИО, телефоны и e-mail в контекст не попадают — подставляются после генерации из `school_contacts`.
- Результат модели — черновик: пользователь правит его в панели, добавляет комментарий (п. 17) и
  нажимает «Отправить»; автоотправки нет. Номер вида `ОБР-2026-000045` присваивается после отправки.
- После отправки: письмо на e-mail провайдера, PDF сохраняется, провайдер видит обращение в своём
  кабинете и меняет статус. Статусы — те же шесть, что у инцидента (ADR-007), переходы — в `appeal_events`.
  Эндпоинты — plan.md §10: `POST /api/appeals/draft`, `POST /api/appeals`, `PATCH`, `GET /api/appeals/{id}/pdf`.

## Последствия
- Промпт и сборка контекста живут только на сервере; панель получает готовый текст. Тест сборщика
  контекста обязан проверять, что полей `school_contacts` в промпте нет.
- Смена модели или провайдера — настройка или новый класс адаптера; логика обращений не меняется.
- Кода пока нет: адаптер — T-46, черновик и редактор — T-47, номер, отправка, PDF — T-48.

## Открыто
- Почтовый сервер: SMTP заказчика. До его настройки PDF сохраняется, обращение помечается «не отправлено».
- Поведение при недоступной модели: по умолчанию черновик пустой, пользователь пишет текст сам.
