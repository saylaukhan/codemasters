# ADR-012 · Движок замеров и методика

**Статус:** принято · **Дата:** 2026-09-16 · **Источник:** ТЗ п. 2, п. 10, п. 11, plan.md §1, §2, §4.3, §4.5, §16

## Контекст
ТЗ п. 2 задаёт минимум метрик (Download, Upload, Ping, состояние подключения, время) и дополнительные
(Jitter, Packet Loss, длительность, внешний IP, сервер, Ethernet/Wi‑Fi). П. 10 требует оценивать линию
школы, а не Wi‑Fi рабочего места. Провайдер будет оспаривать цифры (plan.md §16): метод должен быть записан.

## Решение
- Движок скорости: свой LibreSpeed (основной) и ndt7-server (резервный), оба в казахстанском ЦОДе;
  в compose — сервис `speedtest`, конфигурация в `deploy/speedtest/`. Адрес сервера приходит из
  `GET /api/agent/config`, в агент не зашит (ТЗ п. 20 — удалённое изменение конфигурации агента;
  по аналогии с порогами п. 11).
- Сначала проверка связи: HTTP 204 до своего сервера и DNS; связи нет — `connection_status = offline`.
  Затем Download и Upload по 10 с на направление, несколько потоков; LibreSpeed не ответил — тот же
  замер через ndt7. Сервер и метод пишутся в запись замера (`server`, plan.md §5).
- Ping/Jitter/Loss — 30 ICMP-пакетов через 200 мс до сервера замеров (`prometheus-community/pro-bing`):
  ping = медиана RTT, jitter = среднее |RTTᵢ − RTTᵢ₋₁| (RFC 3550), loss = доля потерянных; ICMP закрыт — TCP-connect.
- Каждый замер несёт `measurement_uuid`, `duration_s`, `external_ip`, `server`, `iface_type`, `agent_version`
  (plan.md §5) — сырые числа без оценки; статус ставит сервер (ADR-004).
- Wi‑Fi-замер (`iface_type`) помечается и не участвует в оценке линии и статусе школы; статус линии —
  по всем её Ethernet-устройствам, главная точка — `monitoring_points.is_primary`. Замер привязывается
  к линии по `external_ip` и `lines.ip_ranges`; ушёл через резерв — `line_id` резервной (plan.md §4.5).

## Последствия
- Спор с провайдером решается записью: в каждом замере есть сервер, метод, интерфейс и снимок порогов.
  Методику меняем только новым ADR — иначе история несопоставима.
- Свой движок исключён (ADR-010); сервер замеров — узкое место: отдельная машина с гигабитным
  каналом, ndt7 в резерве (plan.md §16). Нагрузка на канал школы — 20 с трафика на замер, 4 слота в день.
- Кода пока нет: `agent/internal/probe/`, `internal/speed/`, `internal/netinfo/` — T-09, T-10; сервер замеров — T-05.
