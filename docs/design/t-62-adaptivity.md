# T-62 · Адаптивность до 390px: что сделано и что осталось

Задача — `docs/tasks/README.md`, раздел K, T-62. Цель — таблица `DESIGN.md` §9.3: каждая страница
`web/src/pages/` работает на 1024, 768 и 390px без горизонтальной прокрутки, без отдельных
мобильных маршрутов и без компонентов «для телефона».

Разрешённых механик ровно три (`docs/design/README.md` §2): медиазапросы внутри существующих
CSS-модулей, хук `useMediaQuery` (`NARROW_SCREEN` 1024, `PHONE_SCREEN` 768, `COMPACT_SCREEN` 1279 —
`web/src/styles/theme.ts`) и обёртка `ResponsiveTable`. Четвёртой механики нет: если клетка §9.3
не выражается ни одной из трёх, это повод сказать лиду, а не изобретать обход.

Ветка `feature/t-62-responsive-390` собрана из трёх частей (`feature/t-62-grids`,
`feature/t-62-widgets`, `feature/t-62-tables`) — 43 файла, ~1090 строк diff. Больше цели
AGENTS.md §3.5 в 400 строк, поэтому при слиянии её можно разбирать теми же тремя ветками:
они не пересекаются по файлам.

## 2. Что осталось

Порядок — по тому, насколько это заметно человеку.

### 2.1 Вкладки на ≤768 не прокручиваются

§9.3 требует «горизонтальная прокрутка, активная в видимой области». Ant Design 5 вместо прокрутки
складывает лишние вкладки в выпадающее «ещё». Задевает `components/admin/AdminLayout.tsx` (до девяти
вкладок) и `pages/schools/SchoolCardPage.tsx` (шесть).

Делать так: дать обоим `<Tabs>` свой `className` из соседнего CSS-модуля и в нём на ≤768 включить
`overflow-x: auto; flex-wrap: nowrap` для `:global(.ant-tabs-nav-list)`, спрятав
`:global(.ant-tabs-nav-operations)`. Правка на два файла плюс два медиазапроса. CSS-половину не
писали заранее намеренно: правило без `className` мертво и только путает читателя.

### 2.2 Сортировка карточек на телефоне пуста для серверных таблиц

`ResponsiveTable` строит селект сортировки только из колонок с функцией-компаратором, а списки школ,
инцидентов, обращений, замеров и администрирования сортируются на сервере (`sorter: true`). На
телефоне такой список не отсортировать.

Делать так: научить `responsive-table.ts` принимать серверные колонки (`sorter === true`) и отдавать
наружу выбранный ключ и направление, чтобы страница положила их в URL — `useSchoolListView.ts` уже
умеет круговой обмен `sort` через адрес, остальным нужен тот же приём.

### 2.3 Шаг 2 таблиц сделан наполовину

Есть закреплённая первая колонка и прокрутка внутри карточки; нет кнопки «Колонки», которой §3.12
возвращает скрытые второстепенные колонки, нет полупрозрачной кромки 72px с круглой кнопкой «дальше»
и индикатора «Колонки 1–8 из 12». Сейчас на 769–1024 колонки с приоритетом `minor` просто
исчезают — вернуть их руками нельзя.

Делать так: всё внутри `components/ui/ResponsiveTable.tsx` и его модуля, страницы не трогаются.

### 2.4 Мелкие правки, которые части передали друг другу

- `components/appeals/Appeal.module.css`: ячейке «Тема» нужны `min-width: 0` и многоточие, иначе на
  769–1024 длинная тема раздувает `max-content` (правило 2 §3.12).
- `components/admin/Admin.module.css`: `.changes` ограничена 480px, а в карточке журнала аудита она
  теперь лежит внутри `.pairValue` с `white-space: normal` — ограничение мешает.
- `components/admin/Admin.module.css`: после того как `FormDrawer` стал во всю ширину на ≤768,
  `.coordinates` остались в две колонки, а `.picker` — фиксированные 240px.
- `components/analytics/SchoolComparison.tsx`: таблице сравнения нужен свой `className`, чтобы
  правило многоточия в `.compare` не лезло в AntD через `:global`.
- `components/analytics/IncidentAnalyticsTab.tsx`: таблица вкладки «Инциденты» аналитики на
  `ResponsiveTable` не переведена — она не попала ни в одну из трёх частей.
- `components/incidents/IncidentTable.tsx`: у карточки на телефоне нет действия «⋯» с допустимыми
  переходами; заголовок карточки — ссылка на инцидент, этого пока хватает.

### 2.5 Решения, которые нужны от человека

- `components/analytics/report.ts`, `hoursChart`: столбчатый график часов рисует все 24 категории и
  на 390px. §9.3 такой строки не содержит; сжимать до 8–17, как тепловую карту, или оставить —
  решает лид.
- Модальные окна (`IncidentBoard` 560px, `EnrollmentCodeButton`, подтверждения в
  `DevicesAdminPage` и `UsersPage`) оставлены как есть: AntD сам ограничивает ширину по окну, а
  §9.3 просит «во всю ширину» — стоит ли переводить их в нижние листы, вопрос вкуса.
- Таблицы-матрицы намеренно не переведены: «Показатель — Значение — Порог» в карточке инцидента и
  сравнение двух школ читаются как «ключ — значение» и в списке карточек теряют смысл.

## 3. Чего в этой ветке не проверяли

Ни один брейкпоинт не смотрели в живом браузере. Прогнаны `lint`, `typecheck`, vitest (199 тестов)
и `vite build`; утверждения «на 390 нет горизонтальной прокрутки» опираются на чтение CSS, а не на
`document.scrollingElement.scrollWidth`.

Причина: панели без работающего API видно только страницу входа. Как проверять, когда стенд поднят:

```bash
cd web && npm run build && npx vite preview --port 4179
```

Дальше важная тонкость: headless-браузер из образа (`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`)
не делает окно уже 500px и молча кадрирует снимок — экран, снятый с `--window-size=390,844`,
разложен по 500px. Настоящие 390 получаются через страницу-обёртку с `<iframe width="390">`:
iframe создаёт свой viewport, и медиазапросы внутри отвечают на его ширину. Тема переключается
записью `localStorage` ключа `vko-monitor.theme` со страницы того же origin.

## 4. Когда задачу можно закрыть

1. Каждая страница `web/src/pages/` пройдена по таблице §9.3 на 1024, 768 и 390 в обеих темах,
   горизонтальной прокрутки страницы нет нигде.
2. Пункты §2.1–2.4 этого документа сделаны или сознательно отложены строкой в
   `docs/known-limitations.md`.
3. Отдельных маршрутов и компонентов «для телефона» в diff нет.
4. `make check-web` зелёный, отметка о проходе §8 в обеих темах — в записи `docs/worklog.md`.
