# Jyldam · дизайн версии 2: что, где и как работает

Этот документ описывает поведение экранов панели в новом дизайне и сценарии сверх ТЗ, которые
дизайн вводит. Внешний вид, токены и правила — `DESIGN.md`; макеты — `mockups/` (условные
цифры, имена людей в квадратных скобках); решение о переходе — ADR-015; задачи внедрения —
`docs/tasks/README.md`, раздел K. Кода здесь нет: функциональность появляется по задачам, а
не «заодно».

Живой канвас со всеми артбордами: <https://claude.ai/artifact/5LvWm4fgXitGn6rgfKNJq2>
(приватный, доступ выдаёт владелец). Макеты в `mockups/` — те же артборды, сохранённые как
обычный HTML: открываются в браузере без сборки, шрифт Manrope подтягивается с Google Fonts,
без сети рисуются системным шрифтом.

## 1. Что меняется для пользователя

1. **Имя.** Продукт называется Jyldam; в шапке, на входе, в письмах и PDF. Кодовое имя
   репозитория `vko-monitor` не меняется.
2. **Первый экран отвечает словами.** Главная начинается с вердикта («312 школ из 350 сегодня
   в норме») и полосы статусов, а не с восьми счётчиков. Счётчики ТЗ п. 4 остаются ниже.
3. **У школы свой кабинет.** Роль «Школа» больше не видит карту области и аналитику по районам:
   один экран про её интернет, одна кнопка «Сообщить о проблеме».
4. **Метрики по-русски.** «Скорость загрузки · Download», «Отклик · Ping»; у каждой подсказка,
   что это значит для урока.
5. **Один интерфейс на телефоне и на табло.** Те же страницы перестраиваются по ширине; отдельных
   мобильных маршрутов нет.
6. **Два языка.** Переключатель «Қаз · Рус» в шапке и на входе.
7. **Шесть сценариев сверх ТЗ** (§6): календарь каникул и плановых работ, сводка для
   руководителя, оценка поставщиков с актом, экран внедрения, табло, казахский язык.

## 2. Адаптивность: как это работает без мобильных маршрутов

Правило одно: маршрут, страница и данные одинаковы на любой ширине, меняется только компоновка.
Реализация — в трёх местах, и больше нигде:

- **CSS-модули страниц и обёрток** с медиазапросами по брейкпоинтам `DESIGN.md` §9: сетки
  `grid-template-columns` схлопываются, отступы берутся из `--content-padding`, который сам
  меняется в `tokens.css`.
- **Хук `useMediaQuery`** (`web/src/app/useMediaQuery.ts`, уже есть) для перестроек, которые CSS
  не описывает: сайдбар ↔ drawer навигации, таблица ↔ список карточек, поповер карты ↔ нижний
  лист, действия страницы ↔ закреплённая кнопка. Хук читает ширину окна, не user agent.
- **Обёртка `ResponsiveTable`** в `components/ui/`: принимает те же колонки, что AntD `Table`,
  плюс приоритет каждой колонки; при нехватке ширины сворачивает второстепенные во вторую
  строку, затем закрепляет первую колонку и листает остальные, на ≤ 768 рендерит список
  карточек (`DESIGN.md` §3.12, макет `mockups/Tables.html`); страницы об этом не знают.

Что видит пользователь на телефоне (390px), по экранам:

| Экран | Поведение |
|---|---|
| Любая страница панели | шапка: знак, кнопка меню, аватар; навигация — drawer слева по кнопке; поиск — иконка, раскрывается в поле на всю шапку |
| Главная | вердикт, полоса статусов 2 × 2, карта 360px высотой, «Требуют внимания» под ней, показатели столбцом, инциденты списком карточек |
| Списки (школы, инциденты, обращения, устройства, аудит) | кнопка «Фильтры · N» открывает нижний лист с теми же чипами; список карточек: заголовок, пилюля статуса, 2–4 значения парами; сортировка селектом |
| Карточки (школа, компьютер, инцидент, обращение) | один столбец; правая панель сведений и форма смены статуса — ниже основного содержимого; вкладки прокручиваются |
| Карта | карта во всю ширину экрана за вычетом шапки; поповер — нижний лист; легенда сворачивается в кнопку |
| Кабинет школы | один столбец; «Сообщить о проблеме» закреплена внизу; телефоны — кнопкой звонка |
| Черновик обращения | редактор сверху, «Сведения» раскрывающимся блоком под ним; подвал с «Отправить» закреплён |
| Доска инцидентов | горизонтальная прокрутка колонок 280px с привязкой; переход статуса — из карточки, не перетаскиванием |
| Администрирование | поднавигация горизонтальной полосой; drawer во всю ширину |
| Табло | не показывается, ссылка ведёт на главную |

Сенсорный экран: область нажатия 44px, действия строки видны всегда (не по hover), карта
перетаскивается одним пальцем, страница — двумя.

## 3. Кабинеты по ролям

Права ролей (`backend/app/auth/permissions.py`) не меняются: кабинет режет только навигацию и
компоновку, как это уже сделано для провайдера (`PROVIDER_SECTIONS` в `web/src/app/sections.ts`).

| Роль | Что видит | Посадка |
|---|---|---|
| Школа | кабинет школы (§4.2) без сайдбара; в шапке «Моя школа», «Обращения», «Как это работает» | `/schools/{scope.school_id}` — код уже отдаёт `school_id` в `/api/auth/me` |
| Район/город | панель без «Внедрение» на уровне области и без администрирования; главная и списки сужены до района, вердикт — по району | `/overview` |

| Администратор | всё плюс «Администрирование» с календарём | `/overview` |

## 4. Экраны: что, где и как

### 4.1 Главная области и района (`Main.html`)

- **Что.** Вердикт, полоса статусов, карта и «Требуют внимания», полоса показателей ТЗ п. 4,
  последние инциденты.
- **Данные.** Вердикт и полоса статусов считаются из `GET /api/dashboard/summary` (нужны счётчики
  по статусам и дельты к предыдущим суткам, T-60). «Требуют внимания» — школы со статусом
  «Критично» и «Нет соединения», инциденты без ответственного дольше суток, обращения без ответа
  дольше двух дней; сортировка по тяжести, затем по длительности; причина словами берётся из
  основания инцидента (`incident.metric` → фраза из `labels.ts`).
- **Как работает.** Клик по колонке полосы статусов открывает `/schools?status=…`. Период в
  заголовке общий для полосы показателей и карты (в URL). Дельты показываются, только когда есть
  предыдущий период; иначе строка «первые данные».

### 4.2 Кабинет школы (`School.html`, `SchoolPhone.html`)

- **Что.** Один экран для директора или ответственного за интернет: вердикт, три плитки, полоса
  дней, график недели, провайдер и договор, компьютер с агентом, проблемы и обращения, кому
  звонить.
- **Данные.** Всё уже есть в карточке школы (`GET /api/schools/{id}`, `/analytics`, `/lines`,
  `/devices`, `/contacts`, инциденты и обращения школы). Полоса дней — из `m_daily` по статусу
  дня: «Норма», если за день не было проблемных замеров и простоев; «Нестабильно» или
  «Критично» — по худшему замеру дня; «Нет соединения», если был простой; «Нет данных», если
  замеров не было.
- **Как работает.** Вердикт выбирается по статусу школы и по тому, что именно нарушено:
  `normal` → «Интернет в норме»; `unstable`/`critical` при нарушении скорости → «Интернет
  медленнее, чем по договору» (или «чем положено», если договора нет); при нарушении отклика
  или потерь → «Интернет работает с перебоями»; `offline` → «Интернета нет с HH:MM»;
  `no_data` → «Компьютер с агентом выключен». Плитка показывает факт, норму и договор одной
  полосой: заливка цветом статуса метрики, засечки — порог из `thresholds_snapshot` и договорная
  скорость линии. «Сообщить о проблеме» открывает черновик обращения с предзаполненным
  периодом «последние 7 дней» и основной линией. Пилюли обращений в кабинете подписаны словами
  кабинета: «У поставщика», «В работе», «Ждём ответа», «Решено», «Закрыто». Уведомления школе
  уходят на e-mail и в Telegram ответственного, потому что в панели он бывает редко.
  «Как это работает» — статичная страница с пояснением статусов, слотов замеров и что делать,
  если компьютер выключен.

### 4.3 Список школ, карточка школы для области, карточка компьютера

Как в коде сегодня, в новом стиле: таблица без вертикальных линий, полоса показателей вместо
шести карточек, вкладки со счётчиками. Карточка школы для области остаётся на `/schools/:id`;
для роли «Школа» тот же маршрут рендерит кабинет (§4.2) — ветвление по роли внутри страницы,
без нового маршрута. В истории замеров компьютера каждая строка помечает Wi‑Fi пилюлей «не
оценивает линию» и подсвечивает значения хуже порога из снимка этого замера.

### 4.4 Карта (`Map.html`)

Фильтры в URL, кластеры, легенда-пилюля с числами, поповер школы с договорной скоростью рядом
с фактом («8,4 / 50»). Подсказка над картой объясняет прокрутку. Синхронный список нужен для
клавиатуры: маркеры MapLibre недоступны с клавиатуры, школа выбирается из списка.

### 4.5 Аналитика, инциденты, обращения, выгрузки, администрирование

Состав экранов не меняется, меняется стиль и адаптивность (§2). Три уточнения поведения:

- **Инцидент → обращение — один поток.** Отправка обращения из карточки инцидента переводит
  инцидент в «Передан поставщику» автоматически с записью в истории «Статус изменён при отправке
  обращения ОБР-…»; смена статуса обращения поставщиком отражается в связанном инциденте
  подсказкой в правой панели. Сейчас это два независимых действия (см. `docs/product/demo-scenario.md`,
  сценарий 3); задача T-63.
- **Форма смены статуса подсказывает допустимые переходы** под селектом («доступно: В работе,
  Ожидает информации, Устранён») по таблице переходов T-41, а не отдаёт ошибку после «Сохранить».
- **Конструктор выгрузок показывает «Будет выгружено ≈ N строк»** до формирования: нужен
  эндпоинт подсчёта или поле `rows_count` в предварительном ответе (`docs/known-limitations.md`,
  строка T-30); задача T-64.

### 4.6 Вход и служебные состояния (`Login.html`, `States.html`)

Вход получает ссылку «Забыли пароль?»: письмо со ссылкой на смену пароля, срок действия 30
минут, запись в аудит; без SMTP ссылка не показывается, вместо неё контакт администратора
(T-65). Панель уведомлений, тосты с действием, модалка подтверждения, пустое состояние с
действием, ошибка с повтором, скелетон и 404 — по макету, поведение как в коде.

## 5. Тёмная тема

Те же экраны на фоне `#0F1115` с поверхностями `#171A20`; акцент светлеет до `#5B8DFF`, текст
на акцентной кнопке тёмный; пилюли статусов — подложка цвета на 18 % и светлый текст; заливка под
линией графика 16 % вместо 8 %; маркеры карты с обводкой цвета поверхности. Переключатель в
шапке, стартовое значение — системное, выбор запоминается (как сейчас). Макеты `*Dark.html`.

## 6. Сценарии сверх ТЗ

Каждый сценарий ниже — отдельная задача раздела K; здесь описано, как он должен работать, чтобы
задачу можно было оценить и разрезать. Ни один не реализован.

### 6.1 Казахский язык (`SchoolKz.html`, T-66)

- **Где.** Переключатель «Қаз · Рус» в шапке всех экранов и на входе; выбор хранится в профиле
  пользователя (`users.locale`, значение по умолчанию `ru`) и дублируется в `localStorage` до
  входа. `lang` документа меняется вместе с языком.
- **Как.** Второй словарь `web/src/lib/labels.kk.ts` с теми же ключами, что `labels.ts`;
  компонент получает словарь через хук `useLabels()`, строки в компонентах не остаются.
  Числа и даты — `format.ts` по локали `kk-KZ` / `ru-RU`; единицы «Мбит/с», «мс», «%» и
  идентификаторы не переводятся. Письма провайдеру и PDF-сводки — на языке из настройки рассылки
  («Русский · Қазақша · Оба»: «Оба» кладёт две версии в одно письмо).
- **Опорный перевод статусов.** Норма — Қалыпты; Нестабильно — Тұрақсыз; Критично — Сыни;
  Нет соединения — Байланыс жоқ; Нет данных — Дерек жоқ; Новый — Жаңа; Передан поставщику —
  Провайдерге жіберілді; В работе — Жұмыста; Ожидает информации — Ақпарат күтуде; Устранён —
  Жойылды; Закрыт — Жабылды. Термины: Скорость загрузки — Жүктеу жылдамдығы; Скорость отдачи —
  Жіберу жылдамдығы; Отклик — Кідіріс; Сообщить о проблеме — Мәселе туралы хабарлау. Перевод
  проверяет носитель языка до слияния.

### 6.2 Сводка для руководителя (`Digest.html`, T-67)

- **Где.** «Отчёты и экспорт → Сводки»: настройка рассылки слева, предпросмотр справа.
  Доступна Области и Администратору; Район/город настраивает сводку по своему району.
- **Что внутри.** Одна страница A4: вердикт абзацем (сравнение с прошлым периодом, самый
  заметный сдвиг), четыре числа статусов с дельтой, «Требуют решения» до трёх пунктов (поставщик
  с худшей оценкой, район с наибольшим числом «Нет соединения», школы с договором ниже
  норматива), «Худшие школы недели» до пяти, итоги инцидентов (открыто, закрыто, среднее
  устранение, самое долгое без ответа).
- **Как.** Celery beat по расписанию из настройки (день недели, час, Asia/Almaty): собирает
  данные из `m_daily`, инцидентов и обращений, рендерит PDF тем же генератором, что отчёт по
  школе (T-32), отправляет e-mail через SMTP заказчика и сообщение в Telegram с PDF; каждая
  отправка — в `notification_log`. «Отправить сейчас» ставит ту же задачу вне расписания.
  «Скачать PDF» отдаёт текущий выпуск синхронно. Получатели — пользователи панели с ролями
  Область и Район/город плюс произвольные адреса; список хранится в настройке рассылки.

### 6.3 Поставщики: оценка, эскалация, договор ниже норматива, акт (`Providers.html`, T-68)

- **Где.** Раздел «Поставщики» для Области, Района/города (свои школы) и Администратора.
- **Оценка за период.** Для каждого поставщика: школ на основных линиях; доля времени ниже
  договора (сумма длительностей замеров с `contract_ok = false` к сумме всех замеров основных
  линий в рабочие часы); инцидентов; средняя реакция (от «Новый» до первого статуса, поставленного
  пользователем поставщика или «В работе»); среднее устранение (от начала до «Восстановлено»);
  число обращений без ответа дольше N дней (N из настроек, по умолчанию 2). Оценка 0–100:
  100 минус штрафы за долю ниже договора и за просрочки; веса — в настройках, порог «ниже нормы»
  70. Окна плановых работ из календаря (§6.5) исключаются из расчёта.
- **Эскалация.** Обращение или инцидент в «Передан поставщику» без изменения статуса дольше N
  дней получает красную пилюлю «без ответа N дней» в таблице поставщика, на главной в «Требуют
  внимания» и напоминание ответственному в Telegram раз в сутки; правило — в «Правила
  инцидентов».
- **Договор ниже норматива.** Список линий, у которых договорная скорость ниже порога профиля
  (`lines.contract_down_mbps < thresholds.download_min_mbps` или то же по upload). Такие школы
  помечаются «не претензия»: обращение по ним не предлагается, вместо него «Список для
  перезаключения» в XLSX.
- **Акт о несоответствии.** PDF по поставщику за период: таблица замеров ниже договора со
  снимком порогов и договорных значений, итоги по школам, место для подписи. Генератор — тот же,
  что у обращений (T-48). Кнопка «Отправить поставщику» шлёт письмо на `appeals_email` и
  фиксирует отправку в аудите. ЭЦП ставится вне системы; интеграция с документооборотом —
  вопрос заказчику, не задача.

### 6.4 Внедрение (`Rollout.html`, T-69)

- **Где.** Раздел «Внедрение» для Области и Администратора; Район/город видит свой район.
- **Что считается.** «Подключена» — у школы есть хотя бы одно активное устройство; «на связи» —
  heartbeat за последние 15 минут в рабочие часы; «молчит» — нет heartbeat дольше N дней (N в
  настройках, по умолчанию 7); «старая версия» — версия агента ниже текущего релиза; «по Wi‑Fi» —
  последние замеры главной точки идут через `iface_type = wifi`; «нет ответственного» — у школы
  нет контакта.
- **Как.** Списки ведут в карточку школы; «Выдать код» открывает существующий drawer кода
  установки (T-36); «Назначить обновление» ставит целевую версию релиза для выбранных устройств
  (механизм T-50). Напоминание ответственным молчащих школ — та же рассылка, что в §6.2, раз в
  неделю; кнопка «Напомнить ещё раз» отправляет вне расписания.

### 6.5 Календарь каникул, праздников и плановых работ (`Calendar.html`, T-70)

- **Где.** «Администрирование → Календарь» для Области и Администратора; Район/город добавляет
  события для своих школ.
- **Модель.** Таблица `calendar_events`: тип (`holiday`, `vacation`, `maintenance`,
  `working_day`), период, область действия (вся область, район, школа, линии поставщика),
  источник (справочник праздников РК, импорт XLSX, вручную), комментарий, кто добавил.
  Праздники РК загружаются `make seed`; каникулы импортируются из XLSX по приказу управления.
- **Влияние на данные.** В дни `holiday` и `vacation` замеры принимаются и хранятся, но
  доступность не считается, инциденты не создаются, отсутствие сигнала показывается как «Нет
  данных» с пояснением «каникулы»; в окне `maintenance` инциденты по линиям поставщика не
  создаются, окно исключается из оценки поставщика и из актов, ответственные школ получают
  уведомление за сутки; `working_day` применяет рабочие часы школы к выходному. Расчёты статуса
  (T-16, T-18), доступности (T-27) и детекции инцидентов (T-40) получают проверку календаря
  одним сервисом `calendar.is_quiet(school_id, at)`.

### 6.6 Табло (`Wall.html`, T-71)

- **Где.** Маршрут `/wall` для ролей Область и Район/город; открывается кнопкой «Табло» из
  главной в новом окне; полноэкранный режим браузера.
- **Как.** Тёмная тема принудительно, без меню; данные обновляются каждые 60 с теми же
  запросами, что главная и карта; лента событий — последние уведомления области из потока T-42;
  «Сейчас без связи» — школы в `offline` с временем начала. Esc возвращает в панель. Ниже 1280px
  маршрут перенаправляет на главную. Вход по обычной учётной записи; для экрана в приёмной
  создаётся отдельный пользователь с ролью Район/город без права действий (только чтение
  уже обеспечивается ролью).
