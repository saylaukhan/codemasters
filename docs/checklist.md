# Чек-лист перед слиянием в developing

Этот файл заменяет то, что в других проектах называют шаблоном Pull Request: у нас Pull
Request'ов нет (ADR-001), гейт перед слиянием — этот чек-лист. Проходит его автор задачи сам,
перед `git merge --no-ff` в `developing` (`CONTRIBUTING.md` §5). Сам файл не меняется — вы
заполняете его у себя, а итог копируете в запись `docs/worklog.md`: «Что изменилось» — в
строку «Сделано», отметки чек-листа (что пропущено и почему) — строкой про чек-лист,
«Не сделано / отложено» — в строку «Не сделано».

Пустой чек-лист = не сливаем. Пункт «не применимо» отмечается как выполненный с пометкой
«н/п». Пока `Makefile` не появился (T-01), команды `make …` выполняются вручную по
расшифровке целей в `AGENTS.md` §7 (ADR-001).

## Чек-лист

- [ ] `make check` зелёный локально, вывод показан (не пересказан агентом, а запущен вами).
- [ ] Одна задача — одно слияние: лишних файлов нет, «заодно» ничего не поправлено, diff до
      400 строк (больше — режется, первое слияние — каркас).
- [ ] Миграция (если есть): forward-only, применённые ревизии не тронуты, имя
      `YYYYMMDD_HHMM_short_name`; `make db-reset` зелёный; новая таблица по правилам —
      индексы на FK, `created_at` / `updated_at`, RLS при области видимости, hypertable для
      временного ряда, тест в `backend/tests/` (`CONTRIBUTING.md` §6, ADR-003, ADR-008).
- [ ] Эндпоинт (если есть): Pydantic-схемы запроса и ответа, dependency
      `require("<permission>")` из `app/auth`, ошибки по ADR-009 (problem+json, списки
      `{items, total, page, page_size}`), тест «чужой не видит»; контракт обновлён через
      `make openapi`, сгенерированное закоммичено.
- [ ] Агент (если трогали): пороги, расписание и адрес сервера замеров не зашиты — приходят с
      сервера (п. 11, п. 20); очередь не теряет замеры — запись удаляется только после 201/409
      (ADR-006); тест в том же пакете.
- [ ] UI (если есть): по `DESIGN.md` — токены вместо hex, одна Action-кнопка на экран, статусы
      только из `labels.ts`, три состояния (загрузка / пусто / ошибка), проверено в светлой и
      тёмной теме и на 1024px, отметка об этом — в записи в `docs/worklog.md`;
      `DESIGN.md` §8 пройден.
- [ ] Инварианты ТЗ не нарушены (`AGENTS.md` §8): School ID не из запроса, статусы ровно из
      словаря, инцидент не по единичному отклонению, ПД только в `school_contacts`, секреты
      только в окружении.
- [ ] Нет секретов, `print` / `console.log`, `any`, `type: ignore`, `@ts-ignore`.
- [ ] Сгенерированное (`web/src/api/generated/*`, `docs/reference/openapi.json`) и применённые
      миграции руками не менялись.
- [ ] Новое архитектурное решение — есть ADR в этой же ветке
      (`docs/architecture/decisions/`, следующий номер, статус «предложено»).
- [ ] Недоделки записаны в `docs/known-limitations.md` — по строке на каждую, с номером задачи.
- [ ] `docs/tasks/README.md` — статус задачи обновлён (`done (дата)` или `in-progress`, если
      слияние промежуточное).
- [ ] Коммиты — Conventional Commits, с областью по компоненту, где она применима, на
      английском, без подписи ИИ.
