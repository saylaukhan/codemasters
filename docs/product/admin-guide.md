# Инструкция администратора

Как развернуть «Мониторинг интернета ВКО» с нуля, настроить его и выдать школе код установки
агента. Инструкция рассчитана на администратора, а не на разработчика: всё делается командами
из `Makefile` и мышью в админке.

Установка агента на компьютер школы — отдельный документ: `docs/product/agent-install.md`.
Как система устроена внутри — `docs/architecture.md`.

Все команды выполняются **из корня репозитория**, если не сказано иначе.

---

## 1. Что нужно от машины

| Нужно | Зачем |
|---|---|
| Docker и Docker Compose | база, Redis, серверы замеров, прод-стек |
| Python 3.12+ | backend, миграции, наполнение справочников |
| Node.js 24 | сборка панели |
| Go 1.23+ | только если собираете агент на этой же машине |
| git | получить репозиторий |

Диск: считайте от 20 ГБ на базу с историей замеров на год для 350 школ плюс столько же под
хранилище бэкапов, если оно на том же диске. Память: 4 ГБ хватает для разработки, для
боевого сервера — от 8 ГБ.

Порты (их печатает `make help`): api 8000, панель 5173, база 5432, Redis 6379, LibreSpeed
8080, ndt7 8081, Caddy 80 и 443, Grafana 3000. База, Redis и Grafana публикуются только на
`127.0.0.1` — снаружи они не нужны.

## 2. Развёртывание с нуля

### Шаг 1. Получить репозиторий и создать `.env`

```bash
git clone git@github.com:saylaukhan/codemasters.git
cd codemasters
cp .env.example .env
```

`.env` в репозиторий не попадает никогда (`.gitignore`). Единственный файл окружения, который
там лежит, — `.env.example`, и секретов в нём нет.

**Проверка:** `make up` без `.env` откажется работать и напишет
`Нет файла .env — выполните: cp .env.example .env`. Если увидели эту строку — файл не создан.

### Шаг 2. Разобрать `.env`

Значения по умолчанию годятся для локальной проверки. Для боевого сервера обязательно меняются
отмеченные звёздочкой.

| Переменная | Что это |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` \* | имя базы и учётные данные контейнера `db`. Без кавычек, пробелов и символов `$` и `#` — их читает и `make` |
| `DATABASE_URL` \* | подключение с самой машины (`make api`, `make migrate`, `make seed`). Внутри compose хост подменяется на `db` автоматически |
| `REDIS_URL` | брокер Celery и счётчик лимита запросов агентов |
| `AGENT_RATE_LIMIT`, `AGENT_REGISTER_RATE_LIMIT`, `AGENT_RATE_LIMIT_WINDOW_S` | сколько запросов за окно можно одному устройству и одному адресу без токена. `0` — лимит выключен. Недоступный Redis замер не теряет |
| `SECRET_KEY` \* | подпись JWT панели. В бою — длинная случайная строка. Смена разлогинит всех |
| `API_BASE_URL` \* | публичный адрес API: из него строятся ссылки в уведомлениях, письмах и отчётах |
| `TZ` | пояс интерфейса и отчётов, по умолчанию `Asia/Almaty`. Хранение всегда UTC |
| `SPEEDTEST_URL`, `NDT7_URL` | **начальные** адреса серверов замеров. `make seed` кладёт их в настройки, только если записи ещё нет; дальше они меняются в админке, а не здесь |
| `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_URL` | AI-черновик обращения. Пустой ключ — черновик недоступен, текст пишется руками; всё остальное работает |
| `TELEGRAM_BOT_TOKEN` | пусто — канал Telegram отключён |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | почта уведомлений и обращений. Пусто — письмо помечается «не отправлено», обращение и его PDF сохраняются |
| `SENTRY_DSN`, `SENTRY_ENVIRONMENT`, `SENTRY_TRACES_SAMPLE_RATE` | пустой DSN — Sentry выключен, приложение работает как обычно |
| `WORKER_METRICS_PORT` | порт метрик воркера внутри сети compose (9808) |
| `GRAFANA_ADMIN_USER`, `GRAFANA_ADMIN_PASSWORD` \* | вход в Grafana. Пароль по умолчанию `admin` — сменить обязательно |
| `PGBACKREST_STANZA`, `PGBACKREST_REPO1_PATH`, `PGBACKREST_BACKUP_AT`, `PGBACKREST_RETENTION_FULL` | бэкапы: имя стенджа, путь хранилища, время суточного бэкапа (ЧЧ:ММ по `TZ`), сколько полных хранить |
| `CADDY_DOMAIN` \* | домен для TLS. `localhost` — самоподписанный сертификат; реальный домен с DNS на этот хост — Let's Encrypt автоматически (нужны открытые 80 и 443) |

### Шаг 3. Поставить зависимости

```bash
make install
```

Ставит три части: `go mod download` для агента, виртуальное окружение `backend/.venv` с
backend и его инструментами, `npm ci` для панели. Занимает несколько минут.

**Проверка:** появился каталог `backend/.venv` — дальше все команды `make` берут Python
оттуда.

### Шаг 4. Поднять инфраструктуру

```bash
make up
```

Поднимает `db`, `redis`, `speedtest`, `ndt7`.

**Проверка:**

```bash
docker compose ps
```

Все четыре контейнера в состоянии `running`, у `db` и `redis` — `healthy`. База ждёт
healthcheck до минуты, это нормально.

### Шаг 5. Создать схему базы

```bash
make migrate
```

Применяет все миграции Alembic до последней. Миграции forward-only: откатывать их нечем и не
нужно — ошибка исправляется новой миграцией.

**Проверка:** команда заканчивается без ошибки; последняя строка — `Running upgrade …` до
самой свежей ревизии.

### Шаг 6. Наполнить справочники и тестовые данные

```bash
make seed
```

Загружает районы и города ВКО с границами, поставщиков, типы подключения, тестовые школы (у
каждой одна основная линия и точка мониторинга) и пять dev-пользователей.

**Проверка:** команда печатает строку вида
`seed: районов и городов — …, провайдеров — …, типов подключения — …, тестовых школ — …`.
Повторный запуск ничего не портит: записи обновляются по естественным ключам, существующий
пользователь не переписывается, системные настройки, если они уже есть, не трогаются.

Истории замеров `make seed` не создаёт — школы будут «Нет данных», пока не придёт первый замер
от агента. Для демонстрации историю наполняет симулятор: `SIM_ADMIN_PASSWORD='…' make simulate
n=1000 days=90` — он шлёт замеры через тот же API, что и настоящий агент. Аргументы и профили
данных — `simulator/README.md`. На боевом сервере симулятор не запускают: он пишет
вымышленные замеры в те же таблицы.

### Шаг 7. Запустить приложение

Для проверки на своей машине — три терминала:

```bash
make api      # http://localhost:8000, Swagger на /api/docs
make worker   # Celery worker + beat
make web      # панель на http://localhost:5173
```

Для боевого сервера — весь стек в контейнерах за Caddy:

```bash
docker compose up -d
```

Поднимаются все 11 сервисов, включая `caddy`, `prometheus` и `grafana`. Панель и API
открываются по адресу из `CADDY_DOMAIN`.

**Проверка, что сервер жив:**

```bash
curl http://localhost:8000/api/health
```

Ответ — JSON с `"status": "ok"`, версией приложения и временем в UTC.

## 3. Первый вход

Откройте панель и войдите как администратор.

| Логин | Роль |
|---|---|
| `admin@example.kz` | Администратор |
| `oblast@example.kz` | Область |
| `rayon@example.kz` | Район/город (Усть-Каменогорск) |
| `school@example.kz` | Школа (VKO-UK-001) |
| `provider@example.kz` | Провайдер |

Пароль у всех — `Password1`. **Это учётные записи из `make seed`, они только для локальной
проверки и демонстрации.** На боевом сервере заведите настоящих людей на вкладке
«Пользователи» и удалите или заблокируйте тестовых.

Роли отличаются не только кнопками: сервер проверяет права и область видимости отдельно, и
поставщик, например, не видит телефонов ответственных и чужих линий даже через API.

## 4. Что настроить сразу

Всё настраивается в разделе **Администрирование**. Вкладка, на которую нет права, просто не
показывается.

| Вкладка | Право | Что задать |
|---|---|---|
| Школы | `schools:write` | школы, их линии (основная и резервная), точки мониторинга, рабочие часы, договорные значения |
| Договоры | `schools:write` | импорт реестра договоров из CSV или XLSX в линии школ: предпросмотр, затем запись |
| Устройства | `devices:manage` | список компьютеров, блокировка, перепривязка, замена токена |
| Пользователи | `users:manage` | люди, роли, область видимости, Telegram chat id |
| Районы и города | `references:manage` | справочник районов |
| Поставщики | `references:manage` | поставщики и их адреса для обращений |
| Типы подключения | `references:manage` | оптоволокно, ADSL, радиоканал, спутник, мобильная сеть |
| Пороги | `thresholds:manage` | профили порогов: вся область, район или город, конкретная линия |
| Расписания | `schedules:manage` | слоты замеров: вся область, район или город, школа |
| Правила инцидентов | `incident_rules:manage` | по какому показателю и после скольких нарушений заводить инцидент — для всей области или для одной школы |
| Шаблоны писем | `appeal_templates:manage` | тема и текст обращения и претензии поставщику с подстановками, указания модели, шаблон по умолчанию |
| Настройки | `settings:manage` | системные значения (ниже) |
| Аудит | `audit:read` | журнал действий, входов и отказов |
| События | `audit:read` | события инцидентов и уведомлений |

Порядок, в котором это делают на новом сервере: справочники → школы и линии → пороги →
расписания → правила инцидентов → пользователи → коды установки.

### Системные настройки

Одна строка на всю систему, вкладка «Настройки». Значения по умолчанию:

| Настройка | По умолчанию | Смысл |
|---|---|---|
| Адрес LibreSpeed | из `SPEEDTEST_URL` | основной сервер замера скорости |
| Адрес ndt7 | из `NDT7_URL` | резерв; пусто — без резерва |
| Интервал heartbeat | 300 с | как часто агент сообщает, что жив |
| Интервал обновления конфигурации | 900 с | как часто агент перечитывает настройки с сервера |
| Часовой пояс | `Asia/Almaty` | пояс рабочих часов и отчётов |
| «Нет соединения» после | 900 с | молчание дольше этого в рабочие часы — «Нет соединения» |
| Замеров для статуса школы | 3 | сколько последних замеров основной линии сворачиваются в статус |
| Рабочие часы по умолчанию | пн–сб, 08:00–18:00 | с ними создаётся новая школа |
| Минимальная доступность | 99 % | ожидаемая доступность |
| Несоответствие договору | 50 % за 7 дней | доля замеров ниже договорной скорости, считающаяся устойчивой |
| Синхронная выгрузка до | 10 000 строк | больше — строится в фоне |
| Файлы выгрузок хранятся | 7 дней | потом ссылка отвечает 404 |
| Код установки действует | 7 дней | срок жизни кода |
| Срок очереди агента | 30 дней | сколько суток агент хранит замер и насколько старый замер принимает сервер |
| Автозакрытие инцидента | 24 ч | «Устранён» → «Закрыт» |

Пороги, расписание и адрес сервера замеров **никогда не зашиты в агент и панель** — агент
забирает их с сервера сам. Менять их здесь достаточно: переустанавливать агенты не нужно.

### Правила инцидентов для одной школы

Правило по умолчанию действует на все линии области. Школе с особой связью (спутник, радиоканал)
заведите своё правило: **Добавить правило** → «Для кого правило» — «Школа» → выбрать школу → тот же
показатель, но свои N, T и M. Для линий этой школы правило школы заменяет правило области по этому
показателю; остальные показатели считаются по правилам области. Открытый инцидент правила области
дозакрывается как обычно, второй по тому же нарушению не открывается.

### Шаблоны писем

Письмо поставщику пишется по шаблону: сервер заполняет подстановки `{{school_name}}`,
`{{contract_number}}`, `{{metrics}}` и другие фактами обращения (список — под текстом шаблона, клик
добавляет подстановку), модель излагает заполненный шаблон деловым текстом, а без модели редактор
открывается с заполненным шаблоном. Два шаблона есть с установки: «Обращение поставщику» (по
умолчанию) и «Претензионное письмо» — со ссылкой на договор и требованием перерасчёта. Правьте текст
и указания модели как нужно заказчику; шаблон по умолчанию один, его нельзя отключить — сначала
назначьте другой. В редакторе черновика шаблон выбирается в поле «Шаблон письма»; смена шаблона
заменяет текст. ФИО и телефоны в шаблон не пишите: подпись ответственного подставляется после
генерации (ADR-011).

### Импорт договоров

Вкладка **Договоры**: перетащите файл реестра (CSV или XLSX, до 2 МиБ). Колонки — первая строка;
регистр и порядок не важны: `School ID` и `Поставщик` обязательны, `Идентификатор линии`,
`Статус линии` (основная/резервная), `Тип подключения`, `Номер договора`, `Дата договора`
(`ДД.ММ.ГГГГ`), `Download по договору`, `Upload по договору` (Мбит/с) — по наличию. Сначала
показывается предпросмотр: по каждой строке — что изменится, новая ли это линия или ошибка (школа
или поставщик не найдены, вторая основная линия). Строка находит линию по School ID и поставщику
(и по идентификатору линии, если он есть); без такой линии создаёт новую — основную, если у школы её
нет, иначе резервную. Пустая ячейка ничего не меняет, статус существующей линии файл не трогает.
Кнопка **Импортировать** применяет строки без ошибок; в журнале аудита остаётся одна запись
«Импорт» со счётчиками.

## 5. Выдать код установки агента

Код одноразовый, привязывает один компьютер к одной школе и показывается **ровно один раз**:
на сервере хранится только его хэш.

1. Откройте **Школы** → карточку нужной школы → вкладку **Устройства**.
2. Нажмите **«Выдать код установки»** (кнопка видна с правом `devices:manage`).
3. В окне появится код вида `VKO-0011-7F3K9-2QD4X` и дата, до которой он действует.
   Скопируйте его сразу — повторно он показан не будет.
4. Передайте код в школу вместе с командой установки из `docs/product/agent-install.md`.

**Формат кода — `VKO-<4 символа>-<5>-<5>`: три группы после `VKO`.** В `plan.md` §4.1
сохранился старый пример `VKO-7F3K-92QD` — в нём после `VKO` только две группы, он короче и
сервер его не разберёт: установка получит ошибку `invalid_enrollment_code`. Ориентируйтесь на
код, который показала панель.

Для следующего компьютера — новый код. Если код просрочен или уже использован, агент запишет
это в журнал один раз и не будет повторять до перезапуска службы.

## 6. Пользователи и устройства

**Пользователь.** Вкладка «Пользователи»: почта, имя, роль и область видимости (район,
школа или поставщик — в зависимости от роли), при необходимости Telegram chat id для
уведомлений. Пароли хранятся только хэшами. Блокировка не удаляет историю действий
пользователя и действует сразу — сервер перечитывает учётную запись на каждом запросе, а не
ждёт, пока истечёт токен.

**Устройство.** Вкладка «Устройства» или карточка школы:

- **Заблокировать** — агент получает 403 и перестаёт слать замеры; история остаётся.
- **Разблокировать** — возвращает устройство в работу.
- **Перепривязать** — если компьютер переехал в другой кабинет или другую школу.
- **Заменить токен** — если есть подозрение, что токен утёк.

Компьютер, который переставили «с нуля», лучше заблокировать и выдать новый код, а не
чинить старую привязку.

## 7. Журналы

| Где смотреть | Что там |
|---|---|
| Админка → «Аудит» | кто что менял, входы, отказы агентам |
| Админка → «События» | переходы статусов инцидентов, отправленные уведомления |
| `docker compose logs -f api` | ошибки приёма замеров и запросов панели |
| `docker compose logs -f worker beat` | фоновые задачи: инциденты, выгрузки, уведомления |
| `docker compose logs -f db` | база: восстановление, ошибки архивации WAL |

Каждая попытка уведомления записывается отдельно по каналам (панель, Telegram, почта) с
результатом «отправлено», «не удалось» или «пропущено» — по журналу видно, почему письмо не
дошло, даже если канал отключён.

## 8. Бэкапы

Бэкапы — **отдельная надстройка** над основным compose, а не часть его. Причина простая: как
только включён архив WAL, PostgreSQL держит сегменты, пока их не заберёт pgBackRest, и без
забирающего контейнера диск заполнится молча.

Включить:

```bash
docker compose -f docker-compose.yml -f docker-compose.backup.yml up -d
```

Порядок файлов важен. Первый старт сам создаёт стендж и проверяет, что `archive_command`
базы доходит до хранилища; обе команды безопасно повторять.

Разовый полный бэкап руками:

```bash
make backup
```

Проверить, что всё работает:

```bash
docker compose -f docker-compose.yml -f docker-compose.backup.yml exec pgbackrest \
  pgbackrest --stanza=vko info
```

Должен быть хотя бы один `full` и непустой диапазон архива. Признаки беды: бэкап старше
суток, строка «БЭКАП НЕ УДАЛСЯ» в `docker compose logs pgbackrest`, ошибки `archive_command`
в журнале базы.

**Восстановление описано пошагово в `deploy/pgbackrest/README.md`** — от остановки
записывающих сервисов до проверки данных и снятия свежего бэкапа. Повторять его здесь не
стали: два описания одной процедуры однажды разойдутся, а ошибиться при восстановлении можно
ровно один раз.

На боевом сервере смонтируйте под хранилище отдельный диск или сетевой ресурс: по умолчанию
том лежит там же, где данные базы, и от отказа диска не спасает.

## 9. Наблюдаемость

Grafana — `http://127.0.0.1:3000`, только с самого сервера (снаружи порт не публикуется,
смотрите через ssh-туннель). Логин и пароль — из `GRAFANA_ADMIN_USER` и
`GRAFANA_ADMIN_PASSWORD`, регистрация закрыта. Дашборд «Сервер мониторинга ВКО»
подключается сам: запросы к API и их задержка, доля ошибок, приём замеров, задачи Celery и
их длительность, доступность источников метрик.

Это метрики **сервера**, а не качества интернета школ — качество живёт в замерах и смотрится
в панели.

Sentry включается заполнением `SENTRY_DSN`; персональные данные в отчёты не передаются.
Пустой DSN — нормальный режим работы.

## 10. Обновление контракта API и PDF

Если backend менялся, контракт пересобирается одной командой:

```bash
make openapi    # docs/reference/openapi.json + типы панели web/src/api/generated
```

Печатает `openapi: схема записана в ../docs/reference/openapi.json`. Руками ни контракт, ни
сгенерированные типы не правят — их перезаписывает эта команда.

Описание API одним файлом для поставки:

```bash
make api-pdf    # docs/reference/api.pdf
```

Печатает путь и число страниц. PDF собирается из `docs/reference/openapi.json`, поэтому
сначала `make openapi`, потом `make api-pdf`. Сам PDF в репозиторий не коммитится — это
артефакт поставки, который собирается перед передачей заказчику.

## 11. Что пошло не так

| Признак | Причина и что делать |
|---|---|
| `make up`: `Нет файла .env` | не выполнен `cp .env.example .env` |
| `make db-reset`: `Нет POSTGRES_USER / POSTGRES_DB` | в `.env` нет этих переменных или они в кавычках |
| `make migrate` падает на подключении | база ещё не прошла healthcheck (`docker compose ps`) или `DATABASE_URL` указывает на `db` вместо `localhost` при запуске с хоста |
| `make migrate`: `Multiple head revisions` | две ревизии от одной родительской после слияния веток. Порядок задаёт цепочка `down_revision`, а не имя файла; влитую ревизию не трогают — это задача разработчика |
| Панель открывается, но всё пустое | не выполнен `make seed`, либо у пользователя роль без области видимости — тогда он не видит ничего по определению |
| Вход не проходит с верным паролем | учётная запись заблокирована (вкладка «Пользователи») или сменился `SECRET_KEY` — тогда перелогиниться должны все |
| Замеры не приходят с конкретного ПК | устройство заблокировано (403), код установки не был указан при установке, или агент не видит сервер. Диагностика — `vko-agent status` на самом ПК, см. `docs/product/agent-install.md` |
| Школа «Нет данных», хотя ПК включён | вне рабочих часов школы это нормальный показ, а не поломка. Внутри рабочих часов молчание дольше `offline_after_s` даёт «Нет соединения» |
| Письма не уходят | не заполнен SMTP: обращение сохраняется и помечается «не отправлено», PDF остаётся |
| Уведомления в Telegram не приходят | пуст `TELEGRAM_BOT_TOKEN` или у пользователя не задан chat id; каждая попытка видна в журнале как «пропущено» |
| Выгрузка не скачивается | файл старше срока хранения (по умолчанию 7 дней) — постройте заново |
| Инцидентов нет, хотя связь плохая | инцидент не заводится по единичному отклонению: нужно N нарушений подряд или заданная длительность (вкладка «Правила инцидентов») |

Общее правило: если проверка красная или команда упала — покажите её вывод разработчику, а не
отключайте проверку.

## 12. Известные ограничения

Полный список — `docs/known-limitations.md`. То, с чем администратор столкнётся первым:

- **MSI не подписан** — сертификата Authenticode пока нет. SmartScreen предупреждает при
  запуске вручную; тихая установка через групповые политики не страдает.
- **Мастера установки у MSI нет.** Двойной щелчок ставит агент без кода и без кабинета —
  работает только установка командой с параметрами. Команда — в
  `docs/product/agent-install.md`.
- **Серверы замеров работают без TLS**: LibreSpeed и ndt7 слушают 8080 и 8081 напрямую, по
  `http://` и `ws://`, не через Caddy. Решение по сертификату для них принимает лид.
- **В журнале входов виден адрес контейнера Caddy, а не настоящий IP пользователя** — за
  прокси uvicorn не доверяет `X-Forwarded-For` без отдельной настройки.
- **SMTP, Telegram и ключ LLM не настроены** — соответствующие каналы и AI-черновик
  недоступны, остальное работает.
- **Карта берёт подложку с публичных OSM-тайлов** — без интернета подложка не грузится.
- **Восстановление из бэкапа и дашборд Grafana проверены только по документации**, живого
  прогона на боевых данных ещё не было.
- **`make seed` не даёт истории замеров** — только справочники, районы, тестовые школы и
  пользователей. История для демонстрации берётся симулятором (`make simulate`, шаг 6).
  Глубину принимаемой истории задаёт настройка «Срок очереди агента, дней»
  (**Администрирование → Настройки**, по умолчанию 30): симулятор поднимает её до `days` на
  время прогона и возвращает прежнее значение в конце. Если прогон убили `kill -9`, значение
  останется поднятым — верните его там же.
