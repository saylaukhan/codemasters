# Установка агента на компьютер школы

Агент — фоновая служба. Окна, значка в трее и настроек у неё нет: после установки участие
пользователя не требуется, компьютер работает как обычно (ТЗ п. 2, ADR-010).

Где что описано:

- эта инструкция — что сделать на компьютере школы;
- `agent/installer/wix/README.md` и `agent/installer/linux/README.md` — техническое описание
  установщиков (состав пакета, сборка, параметры);
- `docs/product/admin-guide.md` — как администратор выдаёт код установки.

---

## 1. Что нужно заранее

| Что | Откуда |
|---|---|
| Код установки | администратор выдаёт в панели: школа → вкладка «Устройства» → «Выдать код установки» |
| Кабинет | где стоит компьютер, например «Кабинет 12» |
| Адрес сервера | обычно уже зашит в пакет; если сервер свой — уточните у администратора |
| Права администратора на компьютере | установка ставит службу |

Код выглядит так: **`VKO-0011-7F3K9-2QD4X`** — три группы после `VKO`. Он одноразовый,
действует ограниченное время (по умолчанию 7 дней) и подходит **одному** компьютеру. Для
следующего компьютера администратор выдаёт новый.

> В `plan.md` §4.1 остался старый пример `VKO-7F3K-92QD` — в нём после `VKO` только две
> группы. Сервер его не примет: установка завершится ошибкой `invalid_enrollment_code`.
> Берите код таким, каким его показала панель.

Интернет нужен только для связи с сервером мониторинга: агент ходит на него исходящими
соединениями, входящие порты открывать не нужно.

## 2. Windows: установка из MSI

Мастера с полями у установщика **нет**. Двойной щелчок по `VKO-Agent.msi` поставит агент без
кода и без кабинета — такой агент не зарегистрируется. Ставьте командой.

Откройте командную строку **от имени администратора** в папке с `VKO-Agent.msi`:

```bat
msiexec /i VKO-Agent.msi /qn ENROLL_CODE=VKO-0011-7F3K9-2QD4X ROOM="Кабинет 12"
```

Если сервер мониторинга свой, добавьте его адрес:

```bat
msiexec /i VKO-Agent.msi /qn ENROLL_CODE=VKO-0011-7F3K9-2QD4X ROOM="Кабинет 12" SERVER_URL=https://monitor.example.kz
```

Параметры:

| Параметр | Обязательный | Что это |
|---|---|---|
| `ENROLL_CODE` | нет, но без него агент не зарегистрируется | код установки из панели |
| `ROOM` | нет | кабинет, попадёт в точку мониторинга |
| `SERVER_URL` | да | адрес сервера; значение по умолчанию зашито при сборке |
| `LOG_LEVEL` | нет | `debug`, `info` (по умолчанию), `warn`, `error` |

`/qn` — тихая установка, без окон; так же агент раздаётся через групповые политики.

Что делает установка: кладёт `vko-agent.exe` в `C:\Program Files\VKO Monitor\`, создаёт папку
данных `C:\ProgramData\VKO Monitor\` и разрешает записывать в неё учётной записи LocalService,
пишет `agent.yaml`, регистрирует службу `VKOMonitorAgent` (автозапуск отложенный, учётная
запись LocalService, правило брандмауэра на исходящие), запускает её. При первом старте агент
регистрируется кодом и получает свой токен; дальше замеряет по расписанию с сервера.

**Windows SmartScreen может предупредить** при запуске вручную: MSI пока не подписан
сертификатом Authenticode. Это известное ограничение, а не признак подделки; тихая установка
через групповые политики предупреждения не показывает.

### Проверка

```bat
sc qc VKOMonitorAgent
sc qfailure VKOMonitorAgent
"C:\Program Files\VKO Monitor\vko-agent.exe" status
```

Ожидается: у `sc qc` — `START_TYPE : 2 AUTO_START (DELAYED)`; у `sc qfailure` — перезапуски
через 60000 / 60000 / 300000 мс.

## 3. Linux: установка из .deb или .rpm

Параметры задаются переменными окружения самой команды установки — это аналог свойств MSI.

```bash
# Debian, Ubuntu, Astra
sudo env VKO_ENROLL_CODE=VKO-0011-7F3K9-2QD4X VKO_ROOM="Кабинет 12" \
     apt install ./vko-agent_1.0.0_amd64.deb

# RED OS, ALT, RHEL
sudo env VKO_ENROLL_CODE=VKO-0011-7F3K9-2QD4X VKO_ROOM="Кабинет 12" \
     dnf install ./vko-agent-1.0.0.x86_64.rpm
```

| Переменная | Что это |
|---|---|
| `VKO_ENROLL_CODE` | код установки из панели |
| `VKO_ROOM` | кабинет |
| `VKO_SERVER_URL` | адрес сервера; по умолчанию — зашитый при сборке |
| `VKO_LOG_LEVEL` | `debug`, `info` (по умолчанию), `warn`, `error` |

Что делает установка: кладёт `vko-agent` в `/usr/bin/`, заводит системную учётную запись
`vko-agent` без входа (служба работает **не от root**), создаёт `/etc/vko-agent/` и
`/var/lib/vko-agent/`, пишет `agent.yaml`, разрешает группе агента unprivileged ICMP через
`/etc/sysctl.d/90-vko-agent.conf` (без этого ping уходит в запасной метод через TCP), включает
и запускает `vko-agent.service`.

### Проверка

```bash
systemctl status vko-agent
sudo -u vko-agent /usr/bin/vko-agent status
journalctl -u vko-agent -n 50
```

`status` запускайте **от `vko-agent`, а не от root**: root открыл бы `queue.db` и оставил
рядом служебные файлы от root, которые служба потом не перезапишет.

## 4. Что показывает `vko-agent status`

Команда печатает несколько строк — по ним видно, дошло ли дело до регистрации и уходят ли
замеры:

```
Служба VKOMonitorAgent: <состояние>      (на Linux — Служба vko-agent)
Версия агента: <версия>
Сервер: <адрес сервера мониторинга>
Папка данных: <путь>
Устройство: зарегистрировано (device_id 42)
Запущен: <время>
Последний замер: <время>
Очередь на отправку: 0
```

Как читать:

| Строка | Что значит |
|---|---|
| `Устройство: не зарегистрировано` | код не указан, просрочен или уже использован — см. раздел 6 |
| `Последний замер: ещё не было` | агент запустился, но слот ещё не наступил. Первый замер после старта откладывается на случайные 1–15 минут |
| `Последний замер: нет данных (агент ещё не запускался)` | служба не стартовала ни разу |
| `Очередь на отправку: 0` | всё отправлено на сервер |
| `Очередь на отправку` растёт | сервер недоступен. Это не потеря: замеры лежат в очереди и уйдут сами, когда связь вернётся |

Очередь хранит до 30 суток и до 10 000 записей. Запись удаляется только после того, как
сервер подтвердил приём, поэтому обрыв связи и перезагрузка не теряют ничего.

Проверить сеть и замер прямо сейчас, не дожидаясь слота:

```bash
vko-agent probe        # связь, ping, jitter, packet loss, сетевой адаптер
vko-agent measure      # один замер: в очередь и сразу на сервер
```

Полный список команд — `vko-agent help`.

## 5. Где конфигурация, данные и журнал

| | Windows | Linux |
|---|---|---|
| Конфигурация | `C:\ProgramData\VKO Monitor\agent.yaml` | `/etc/vko-agent/agent.yaml` (0640) |
| Данные | `C:\ProgramData\VKO Monitor\` | `/var/lib/vko-agent/` (0750) |
| Журнал | `agent.log` в папке данных | `agent.log` в папке данных и `journalctl -u vko-agent` |
| Служба | `VKOMonitorAgent` | `vko-agent.service` |

В папке данных лежат: `queue.db` — очередь замеров, `agent.log` — журнал, `device.json` —
идентификатор устройства, `device_token` — токен (на Windows защищён DPAPI, на Linux это файл
с правами 600), `agent-config.json` — копия настроек, полученных с сервера, `state.json` —
состояние, `update-state.json` и `updates/` — обновления.

В `agent.yaml` всего пять полей: адрес сервера, кабинет, код установки, папка данных и
уровень журнала. **Порогов, расписания и адреса сервера замеров там нет и быть не должно** —
агент получает их с сервера, и меняются они в админке.

`agent.log` не ротируется. На компьютере, который работает годами, за ним стоит приглядывать.

## 6. Типовые сбои

| Что видно | Почему | Что сделать |
|---|---|---|
| `Устройство: не зарегистрировано`, в журнале — про код установки | код не указан, просрочен, уже использован или от другой школы | взять у администратора новый код, вписать его в `agent.yaml` в поле `enroll_code` и перезапустить службу |
| Агент поставили двойным щелчком | установка прошла со значениями по умолчанию: без кода и кабинета | дописать код в `agent.yaml` и перезапустить службу либо переустановить командой с параметрами |
| Служба постоянно перезапускается (Windows) | если агент ставили вручную через `vko-agent install`, а не из MSI, у LocalService может не быть права писать в папку данных | ставить из MSI: он выдаёт это право сам |
| Очередь растёт, замеры не уходят | нет связи с сервером или неверный `server_url` | проверить `vko-agent probe` и адрес в `agent.yaml`; замеры не теряются |
| Ping подозрительно одинаковый (Linux) | не применился `/etc/sysctl.d/90-vko-agent.conf`, ping идёт запасным методом через TCP | применить sysctl и перезапустить службу |
| Замеры приходят, но школа не та | устройство привязано к другой школе — код был чужой | перепривязать устройство в админке |
| Ошибка `invalid_enrollment_code` | код набран из примера `plan.md` §4.1 или с опечаткой | взять код из панели, формат `VKO-<4>-<5>-<5>` |

Агент сообщает о неудачной регистрации в журнал **один раз** и не повторяет попытку до
перезапуска службы — если исправили код, службу нужно перезапустить.

Правило брандмауэра на исходящие соединения на части систем может не создаться
(установка при этом не прерывается) — если замеры не уходят, проверьте исходящие правила
вручную.

## 7. Переустановка, удаление, обновление

**Удаление.** Windows — «Программы и компоненты» или `msiexec /x VKO-Agent.msi /qn`.
Linux — `sudo apt purge vko-agent` или `sudo dnf remove vko-agent`.

Папка данных, `agent.yaml` и учётная запись `vko-agent` **остаются намеренно**: в папке лежат
неотправленные замеры и токен устройства. Повторная установка подхватит их и нового кода не
потребует.

**Поставить компьютер «с нуля»:** удалить программу, затем удалить папку данных вручную и
заблокировать прежнее устройство в админке — иначе в списке останутся два компьютера.

**Обновление.** Установка новой версии поверх старой папку данных и очередь не трогает, код
установки и кабинет из `agent.yaml` сохраняет. На Linux самообновления нет: новая версия
ставится пакетом. На Windows служба умеет применить скачанный релиз сама.
